# RiftBroadcast 广播视觉规范（参考图复刻）

参考素材（用户提供，2026-11-12）：
- docs/reference/bp-lineup-reference.jpg —— BP/阵容页，2324×1311
- docs/reference/ingame-hud-reference.jpg —— 局内 HUD，2306×1312

目标：动画端按这两张图的排版与视觉语言 1:1 复刻，数据全部来自本应用。

## 一、BP 页（图 1）

结构从上到下：
1. 顶部品牌条：通栏黑底（约 64px 高），居中「赛季徽记 26」+ 竖分隔线 + 赞助商 HYPERX；文字白色、字重 700。
2. 主画面：选手摄像头/英雄原画全屏铺满。浏览器源里用可配置的选手大图或队伍色渐变占位；OBS 场景可把摄像头视频源叠在下方。
3. 底部横带（约占屏高 30-32%，纯黑 #05070a；1920 实现取 32%，1366/1600 用紧凑行高保证角色行与 PATCH 可见）：
   - 教练行（36px）：左 COACH: xxx，右 COACH: xxx，14px 灰白。
   - Ban 行（56px）：左右各 5 个 44×44 禁用英雄小图标，圆形/方形裁切，低饱和。
   - 青色品牌分隔线：3px，#22d3ee，贯穿全宽。
   - 阵容区：左右各 5 格，每格约 220×260，英雄原画竖切（object-fit: cover, object-position: top）；
     格底左下选手 ID（16px 700 白色），右下 2 个召唤师技能小图标（18×18）。
   - 空态约定：mock 模式显示 `DEMO DATA`；live 模式仅在 LCU `draft.parsed=true` 且已有 pick/ban 时视为真实 BP，空 session 使用 `config/broadcast.json` 的选手名单占位并显示 `DEMO DATA`，不读取 `state.players` 的启动 mock/上一局数据。
4. 中央信息块（夹在左右阵容之间，宽约 420px，黑底）：
   - 顶部赞助商小 logo
   - 73.3% / FEARLESS PB%：主数字 44px 700 金色 #f5c451；标签 12px 灰
   - 26.7% PICK：26px 白色
   - 16W - 8L：14px 灰
   - BLUE SIDE ◀ 1ST PICK：12px 青色
   - 两队队标（96×96）+ 队名（28px 700）
   - PATCH 26.20：11px 灰

配色 token：
--bg:#05070a; --panel:#0b0f14; --cyan:#22d3ee; --blue:#3b82f6; --red:#ef4444; --gold:#f5c451; --text:#e5e7eb; --muted:#94a3b8

动画（入场 0-1200ms，时间驱动，与数据无关）：
- 顶部品牌条：translateY(-100%)→0，250ms cubic-bezier(.2,.8,.2,1)
- 底部横带：translateY(100%)→0，300ms 延迟 100ms
- 教练/ Ban 行：opacity 0→1 延迟 250ms
- 5 个英雄格：从左/右分别 stagger 40ms 滑入 + 青色描边闪光 200ms
- 中央信息块：scale(.96)→1 + opacity，延迟 450ms
- PB% 数字：0→73.3% 计数 600ms ease-out
- 阶段切换到 BP 时整体重播一次（重新挂载即可）

## 二、局内 HUD（图 2）

1. 顶部比分条：水平居中，宽约 55%（1050px），高 90px，黑底 0.92 不透明度，底部 2px 队伍色渐变线。
   左→右：队标 44×44 + 队名 22px 700 + 赛区排名 11px 灰；击杀（骷髅图标+数字 26px）；金币（10.0K，20px）；推塔（图标+数字）；中央时间 06:04（28px 700，等宽字体）；镜像右半。
   时间下方经济差 +0.7K（红/蓝，14px 700，正负号）。
   比分条下方一行目标图标（塔/小龙/大龙/巢虫/先锋），各 20×20，左右各一组，灰/亮表示已获取。
2. 底部积分板：贴底，高约 150px，左右镜像 5 行；每行：
   等级（24px 方形）→ 英雄头像 40×40 → 6 格装备 22×22 + 饰品 → 选手 ID 14px → CS 18px → KDA 18px（0/0/0 格式）。
   蓝方左半从左到右，红方右半从右到左镜像。
3. 左下角：选手摄像头 220×160（带姓名条）；右下角：小地图框 220×220（圆形/方形描边 + 队伍色）；左下赞助商条 260×90 可轮播。
4. 左上角：小计时器 1:56（可选，显示下一场倒计时）。

动画：
- 比分条入场：translateY(-120%)→0 300ms；击杀数字变化时 1.15 倍弹跳 180ms；金币数字 tween 400ms；经济差翻转方向时颜色渐变 200ms。
- 底部积分板入场：translateY(100%)→0 320ms，5 行 stagger 30ms。
- 目标图标获得时：scale 1→1.35→1 + 发光 400ms。
- 小龙/大龙倒计时：最后 30 秒数字脉冲 1s 循环。
- 击杀事件：顶部比分条对应方数字抖动 + 侧边红光扫过 300ms。
- 页面切换：0.35s 斜切 wipe（伪元素 skewX(-12deg) 从右到左）。

## 三、工程约定
- 纯 HTML + CSS + 原生 JS，零运行时依赖；动画用 CSS keyframes + Web Animations API。
- 所有动画包在 @media (prefers-reduced-motion: reduce) 下降级为淡入。
- 每个动画页面必须能在 OBS 浏览器源 1920×1080 下透明背景渲染。
- 数据缺口：金币/经济差只能估算或显示装备价值差；选手摄像头由 OBS 视频源提供，页面留空位；PB%/战绩/教练/赛区排名来自 config/broadcast.json。
